## 1. 왜 이런 일이 생기나 (코드 근거)

### 앱이 직접 만드는 계정

`lib/services/store.dart:180-195` — `init()` 은 **매 부팅마다** 실행됩니다:

```dart
await _ensureMaster();
await _ensureTestUser();
```

`_ensureMaster()` (`store.dart:203-213`):

```dart
if (!_users.containsKey(masterId)) {
  final master = User(
    id: masterId,
    password: _randomPlaceholder(),   // ← 64자리 난수
    displayName: 'Master',
    isMaster: true,
  );
  await _users.put(masterId, master.toMap());
}
```

`_randomPlaceholder()` = uuid v4 두 개를 붙인 64자 hex. **아무도 이 값을 모릅니다.**

### 그래서 생기는 두 증상

**① "이미 있는 계정입니다"** — `addUser()` (`store.dart:941`):

```dart
if (_users.containsKey(trimmed)) return 'That ID already exists.';
```

기기 로컬 박스에 이미 `june7486` 이 있으므로 **서버를 보지도 않고** 거부합니다.

**② "비밀번호가 안 맞습니다"** — `authenticate()` (`store.dart:436-470`):

```
1) 서버 명부 대조 (authenticateAgainstRegistry)
   · 서버 응답 OK + 해시 일치 → 통과
   · 서버 401/오류        → null → 아래로 폴백
2) 폴백: local.password == 내비번 ?
   · local.password 는 64자리 난수 → 절대 불일치 → 실패
```

## 3. 해결 — 한 줄

```bash
sudo python3 fix_master.py data --pw '내가 쓸 비밀번호' --name '이승준' --apply --yes-i-mean-it
```

**하는 일**: 명부 + 마스터 워크스페이스에 `june7486` 을
`isMaster=true, enabled=true, pwHash=<새 비번>` 으로 심습니다.
**다른 계정과 일정은 건드리지 않습니다.** 평문 비번은 저장하지 않습니다.
실행 전 자동 백업(읽기 검증 포함).

**단, 게이트웨이가 살아 있어야 실행됩니다.** `(다) /health` 가 `ERR` 이면
먼저 서비스를 켜십시오:

```bash
sudo systemctl status june-gateway    # 상태 확인
sudo systemctl restart june-gateway   # 꺼져 있으면 기동
curl -s localhost:8097/health         # {"ok":true,...} 나오면 정상
```

게이트웨이가 죽은 채로 계정만 고치면 **앱은 여전히 로그인에 실패합니다**
(앱이 명부를 못 읽으므로 로컬 난수로 폴백). 그래서 도구가 먼저 막습니다.

**검증 5종이 자동 출력됩니다**:
비번 해시 일치 / 마스터 권한 / 활성 상태 / 평문 없음 / 서버가 같은 해시 제공

## 5. 401 함정 (계정보다 먼저)

### 401 이면 앱이 명부를 못 읽습니다

앱은 키를 보낼 수단이 없습니다(로그인 화면에 서버 주소/키 입력란이 없음).
그래서 401 → 폴백 → 로컬 난수 → 실패.

```bash
sudo cp .env .env.bak.$(date +%Y%m%d-%H%M%S)
sudo sed -i 's/^SYNC_SECRET=.*/SYNC_SECRET=/' .env
sudo systemctl restart june-gateway
```

`HOST=127.0.0.1` 이므로 루프백 밖에서는 접근 불가 — 안전합니다.

## 10. 새로 발견한 보안 구멍 (같이 보고)

### 잠근 아이디는 **재가입으로 되살릴 수 있습니다**

`registryConflict()` (`store.dart:888-901`) 는 이렇게 판정합니다:

```dart
if (raw['enabled'] == false) return null;
// "A retired row is not a conflict: the id is free to be claimed again"
```

그리고 `addUser()` 는 `publishAccountToRegistry(u, withPassword: true)` 를 부릅니다.
→ **독극 해시(`0000…0`)를 새 해시로 덮어씁니다.**

즉 `reset_accounts.py` 의 묘비는 **옛 기기**를 막지만,
**새 가입자**는 막지 못합니다. 워크스페이스 코드(`ACC…`)는 아이디에서
결정적으로 계산되므로, 재가입자는 이전 일정을 그대로 물려받습니다.

**실측**: `june7558` 재등록 → `ACC8A71DAB5525E1EDBB020742F189C` → 일정 3개 그대로 노출.

### 그래서 판단 기준

| 옛 데이터 | 권장 |
|---|---|
| **살려야 한다** | 묘비만 (지금 상태). 대신 아이디를 **본인이 먼저 재등록**해 선점 |
| **버려도 된다** | `reset_accounts.py --purge-data` → 일정까지 삭제 |

근본 수정은 앱 코드에서 두 줄이 필요합니다(다음 빌드 때):
1. `registryConflict()` 에서 묘비도 충돌로 처리
2. `addUser()` 에서 `retiredAt` 있는 행은 재사용 금지

이번 문서에서는 **손대지 않았습니다.** UI·동작 변경이라 승인 없이는 안 합니다.
