## 2. 진짜 문제 — 업데이트 알림이 동작할 수 없는 구조

### 운영 서버의 실제 응답

```
GET https://www.aqdesign.co.kr/version.json
{"app_name":"june_scheduler","version":"1.0.0","build_number":"1","package_name":"june_scheduler"}
```

**`build` 필드가 없습니다.**

### 앱의 판단 로직 (update_service.dart)

```dart
remoteBuild = (body['build'] ?? body['build_id'] ?? '') as String?;
...
if (remoteBuild == null || remoteBuild.isEmpty) return null;
```

`build` 가 없으면 `null` → 호출자는 "확인 불가"로 처리 →
**새 빌드가 배포되어도 사용자는 영원히 모릅니다.**

### 왜 없어졌나 — 세 겹

1. `flutter build web` 은 `version.json` 을 기본값으로 **덮어씁니다**.
   기본값에는 `build` 가 없습니다.
2. `scripts/write_version_json.py` 라는 도구는 있었지만
   **어떤 배포 스크립트도 부르지 않았습니다** (grep 0건).
3. `deploy_pages.sh` 는 `--dart-define=BUILD_ID` 를 **앱 안에만** 심었고
   파일로는 내보내지 않았습니다.

## 3. 고친 것

### deploy_pages.sh — ③-3 단계 추가
누출 검사 직전, gh-pages 커밋 직전에 `version.json` 을 씁니다.
`--build-dir` 을 **반드시 명시**합니다. 생략하면 기본값(프로젝트
build/web)으로 가서 엉뚱한 곳에 쓸 수 있습니다 — 실제로 시험 중에 그 일이
났고, 검사 장치가 잡아서 망정이지 아니었으면 "심었다"고 보고하고 빈 파일을
배포했습니다.

심은 뒤 **파일을 다시 읽어 값이 같은지 확인**하고, 다르면 배포를 중단합니다.

### deploy_gabia.py — 같은 구멍 막음
이 스크립트는 **이미 빌드된** build/web 을 올립니다. 그래서
`main.dart.js` 에서 BUILD_ID 를 읽어(`read_build_id_from_bundle`)
`version.json` 에 같은 값을 씁니다.

**배포 시점에 새 시각을 만들면 안 됩니다.** 앱 안의 값과 파일의 값이
어긋나면 앱이 자기 자신을 "구버전"으로 인식해 영원히 "새 버전 있음"이라고
말합니다.

팝업이 뜨면 스크림이 여백을 어둡게 덮습니다. 이게 유일한 고유 신호입니다.

### 시험이 잡아낸 제 실수 3건

1. **판정 기준이 틀렸습니다.** 처음엔 "명암 대비"로 팝업을 판정했는데,
   로그인 화면도 대비가 220 이라 팝업(239)과 구분이 안 됐습니다.
   스크린샷을 직접 열어보니 A와 C가 **바이트 단위로 동일**(35,932 B)했고
   로그인 화면이었습니다. → 스크림 기준으로 교체.
2. **서버 로그가 쿼리를 잘라버렸습니다.** `_=` 캐시 무력화 쿼리가 붙었는데도
   "없다"고 거짓 보고했습니다. → 원본 경로 기록으로 수정.
3. **시험이 실제 배포본을 덮어썼습니다.** `--build-dir` 누락 때문.
   → 격리 디렉터리로 바꾸고, 시작 시점 해시와 비교해 무변경을 검증.
