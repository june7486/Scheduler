## 2. 계정이 저장되는 구조

계정 정보는 **세 곳**에 나뉘어 있고, 성격이 다릅니다.

| 위치 | 무엇이 있나 | 평문 비번 | 비고 |
|---|---|---|---|
| 서버 `data/ACCREGISTRYJUNESCHEDULER0001.json` | 아이디·표시이름·권한·활성여부·`pwHash` | **없음** | 계정 명부(레지스트리). 모든 기기가 보는 권위 |
| 서버 `data/ACC….json` (계정별 워크스페이스) | 그 계정의 일정·카테고리·로그 | **없음** | `pwHash`만. 구버전 행은 정리됨 |
| 기기 로컬 `users` 박스 | `password` **평문** | **있음** | 오프라인 로그인용. 기기 밖으로 안 나감 |

즉 **서버를 뒤져서 비밀번호를 알아내는 것은 불가능**합니다. 서버에는 `pwHash`만 있습니다.

그런데 **기기 로컬에는 평문이 남습니다.** 그 기기를 잡은 사람은 읽을 수 있습니다. 이건 트레이드오프입니다 — 오프라인에서 로그인하려면 필요합니다.

### 해시 방식
```
seed = "june-scheduler-pw-v1|<아이디 소문자>|<비밀번호>"
d    = sha256(seed)
256회 반복: d = sha256(d + seed)
저장 = d.hex()
```
SHA-256 256회 반복. GPU 공격에 강하지는 않습니다. 아이디가 솔트 역할을 하므로 같은 비번이라도 계정마다 해시가 다릅니다.

**이 계산을 Python으로 재현해 Dart 결과와 바이트 단위로 일치하는 것을 확인했습니다.** 그래서 아래 점검 스크립트의 판정을 신뢰할 수 있습니다.

## 4. 발견한 문제 — 심각도 순

### (가) 데모 계정 `test` / `test` 가 운영에 살아 있음

`store.dart:190`에서 **앱이 부팅할 때마다** `_ensureTestUser()`를 호출합니다.

```dart
await _ensureMaster();
await _ensureTestUser();   // ← 매번
```

`_ensureTestUser()`는 `test` 계정이 없으면 만들고, `enabled: true`로 심습니다. 비밀번호는 리터럴 `'test'`.

**측정 결과** (실제 Store로 검증):

| 측정 | 결과 |
|---|---|
| 신규 설치 + 서버 없음 → `test`/`test` 로그인 | **통과** |
| 데모 계정 `isMaster` | false |
| 관리자 화면 접근 | 차단됨 (`store.isMaster` 게이팅) |
| **다른 계정 삭제** | **가능** (`deleteUser`에 권한 검사 없음) |
| 관리자(master) 계정 삭제 | 차단됨 (코드 가드 있음) |
| 데모 계정 삭제 후 앱 재시작 | **되살아남** |
| 번들에 코드 포함 | **포함됨** (`Sample to-do` 문자열 확인) |

**피해 범위**: 데모로 로그인하면 **자기 워크스페이스만** 보입니다. 주인 일정은 안 보입니다.
그런데 **다른 계정을 지울 수 있습니다.** 관리자 화면은 못 들어가지만 `deleteUser` 자체에는 권한 검사가 없습니다.

**대응**: 재빌드 필요. `_ensureTestUser()` 호출을 릴리스에서 제거하거나 `enabled: false`로. 지금은 재빌드가 범위 밖이라 **하지 않았습니다.**
